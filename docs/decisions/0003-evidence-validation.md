# ADR 0003: deterministic evidence and advisory challenges

Status: accepted for Milestone 3.

Evidence quantity, independently collected source diversity, methodological quality and
claim applicability are distinct. An AI proposal cannot establish any of them.

Use immutable, claim/population-scoped assessments and validated versioned TOML policies
outside prompts. Keep conservative ordinal weakest-dimension quality, explicit freshness
reasons, provenance/family connected components and independent-method matching. Keep
risk as a monotonic ordinal impact/uncertainty lookup, not probability arithmetic.

Reuse the eighteen validation methods in the domain and re-export the same enum at its
existing application import path. Add versioned validation snapshots, criteria-specific
versions and append-only result recordings with before/after assumptions and matching
audits. Retain existing Milestone 1 freshness behavior and Milestone 2 proposals.

Challenge Mode is one additional structured provider capability behind an application
protocol, with the OpenAI SDK confined to infrastructure. Retain advisory output,
contradictions and provenance; reject authoritative state/decision fields. Extend the
existing offline/live evaluation paths and require no new dependencies or workflows.

Consequences: reviewer basis and canonical origin identity still need human accountability.
Callers must retain full records; persistence transactions and authorization are deferred.
The conservative quality rule can remain low despite useful evidence. Read dimensions
and limitations, not just an aggregate. No Milestone 4 gates are implemented.
