# Product Discovery Engine v0.1.0

**Release-note draft.**

The full v0.1 functional lifecycle is complete: product signals and structured hypotheses
lead through evidence, validation, accountable delivery decisions, reviewed specifications,
implementation records, measured outcomes and evidence feedback. The system is a Python
modular monolith with credential-free examples, including a search case ending in a
human-reviewed MIXED outcome and unresolved causality.

## Key capabilities

- Immutable original inputs, scoped claims, explicit unknowns, evidence provenance and matching audits.
- Deterministic evidence quality/freshness, source independence, assumption risk and recorded validation.
- Separate Discovery Priority, Delivery Readiness and Discovery Gate, followed by human selection.
- Optional AI interpretation, Challenge Mode and specification proposals with retained provenance and human review.
- Versioned DeliverySpec, qualitative completeness, owned clarification, exact review, Delivery Gate and separate handoff.
- Supplied actual implementation scope/deviations, versioned measurement plans, baselines, targets and observations.
- Per-metric target evaluation, separate human causal interpretation, appended outcome evidence, follow-up links and reviewed closure.

## Architecture principles

AI interprets and drafts; deterministic code governs policy; humans remain accountable.
The pure domain depends on no provider, storage, UI or HTTP framework. Versioned TOML
policy and dedicated lifecycle operations enforce exact content/version bindings. Unknowns
and contradictions stay visible. A gate pass does not select work, and a met target does
not prove causality. Closed means a reviewed episode.

## Offline verification

The credential-free suite passed **1,099 tests**. Ruff lint and format checks, strict mypy,
wheel build, dependency checks and all five offline examples passed. The **18 live AI checks
were intentionally skipped/deferred** and are not counted as passed.

Offline fixtures, fake providers and mocked SDK transport verify deterministic behavior
and AI contracts. Live model semantics remain unverified; the
[deferred verification checklist](../evals/deferred-live-verification.md) tracks a separately
authorized future phase. No paid model call is required to run the normal suite or examples.

## Known limitations

No production database, authenticated actors/RBAC, web UI, external analytics connectors
or automated deployment is included. Callers supply current records and retain full
snapshots/sources/audits; transactions and concurrency control remain future work. Nested
history has storage/validation costs. Source truth, requirements meaning and experimental
validity still need accountable human judgment.

Production storage, access control, integrations, deployment, observability/performance and
live model verification are outside the v0.1 scope.
